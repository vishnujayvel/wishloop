Architecture comparison and integration analysis for your SDLC orchestration stack

1 OpenSpec + Loki Loop: 9-Phase Pipeline

Born from a real failure: Loki shipped 9 bugs because the spec pipeline had no feedback loop. This system closes that gap: spec → execute → verify → file bugs → learn → loop.

Loop until 0 bugs or max 5 iterations

2 Key Components

◆ OpenSpec CLI

  • Generates delta specs (ADDED / MODIFIED / REMOVED)
  • Artifacts: proposal.md, design.md, specs/, tasks.md
  • Validation gate before execution
  • Archive command for post-run cleanup
  • Install via npm: openspec CLI

◆ Loki Mode

  • Multi-agent autonomous execution engine
  • Reads CLAUDE.md for project context at startup
  • Parallel agent spawning with --parallel flag
  • Dashboard at localhost:57374
  • Requires --dangerously-skip-permissions

◆ Gardening Agent

  • 5-minute polling loop during Loki execution
  • 5 checks: commits, STATUS.txt, agents, build, conflicts
  • Anomaly detection: stalls, crashes, build breaks
  • Steering commands: PAUSE / STOP / HUMAN_INPUT
  • Journals to docs/plans/pipeline-journal.md

◆ Institutional Learning

  • Stored at ~/.local/share/wishloop/
  • learnings.json: categorized by tech/loki/workflow/testing
  • Injected into CLAUDE.md before each Loki run
  • Deduplication across entries
  • Run instance records for history

! Current Worktree Handling (Pain Point)

Today, worktree isolation is handled via references/worktree-isolation.md — a manual reference doc. No tooling, no lifecycle management, no merge automation.

Manual git worktree add

Type branch name 3 times. cd into path manually. Hope you remember the naming convention.

Manual cleanup

cd back, git worktree remove, git branch -d. Easy to leave orphans.

No merge automation

Squash, rebase, ff-merge, cleanup are all separate manual steps.

◆ Worktrunk: Purpose-Built Worktree Manager

Rust CLI by max-sixty. Most popular git worktree manager. Built for running AI agents in parallel.

MIT / Apache-2.0 Rust (unsafe = forbid) brew install worktrunk

Key Insight: Different Layers, Not Competitors

  • OpenSpec-Loki answers: "What should we build? Is it right? What did we learn?"
  • Worktrunk answers: "Where does each agent work? How do we merge the results?"
  • Your current system has a gap in the middle — worktree management is manual and fragile
  • Worktrunk fills that gap precisely, without overlapping with the spec/verify/learn loop

➤ Migration Path

Install Worktrunk

brew install worktrunk && wt config shell install. Zero risk, additive only.

Add project hooks

Create .worktrunk.toml with post-start hooks (npm install, copy caches) and pre-merge hooks (test suite, lint).

Update Phase 5 in SKILL.md

Replace nohup loki start ... & with wt switch -c -x "loki start --parallel" <change>. Loki runs inside worktree.

Enhance Phase 6 gardening

Gardening agent calls wt list --json for structured status instead of raw git parsing. Same anomaly detection, cleaner data.

Wire pre-merge hook to Phase 8

WT pre-merge hook runs build + test + type-check. Failed pre-merge blocks wt merge. Issues filed automatically.

Wire post-merge hook to archival

WT post-merge hook runs openspec archive <change> + captures run instance. Worktree cleaned up automatically.

Delete references/worktree-isolation.md

The manual reference doc becomes obsolete. Worktrunk handles the entire worktree lifecycle.

Verdict: Integrate, Don't Replace

  • Worktrunk is not a replacement for your loop — it has no spec generation, no verification, no learning, no autonomous iteration
  • Worktrunk replaces the weakest part of your stack — the manual worktree management that's currently just a reference doc
  • The hook system is the bridge — WT hooks map cleanly to your existing phases (pre-merge = Phase 8, post-merge = archival)
  • Bonus capability — parallel bug-batch waves become trivial: wt switch -c -x claude wave-1, wt switch -c -x claude wave-2
  • Rename opportunity — with Worktrunk handling the "loop" orchestration at the git layer, the skill name can drop "loop" and become simply "loki" or "specloop"
